# V1.0 Sub-project 4b — AI Questions, Draft Reports and Shareable Summaries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let participants ask cited AI questions about project material (private, shareable into threads when safe), request AI draft reports and specifications, and let PM/Owner/Sponsor approve sanitised summaries of restricted sources for a wider audience.

**Architecture:** A passage index (`passages`, two `tsvector` columns) is written whenever an immutable source, message or summary version is stored; records are searched live with expression indexes. One search function picks material within a *personal* or *thread* scope and the result is stored per request. A new `assist` module holds requests, answers, report drafts and summaries; one worker handler on the existing `ai` queue runs all three kinds through `guardedAiCall`. A single removal hook, called from moderation and audience tightening, withdraws private outputs and sends shared ones to review.

**Tech Stack:** TypeScript, NestJS 12, PostgreSQL 16 (plain SQL migrations with checksums), pg-boss 12, React + Vite, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-15-v1-ai-assist-design.md` (read it in full first; section numbers below refer to it). Also read the 4a spec `docs/superpowers/specs/2026-11-11-v1-discussion-design.md` §6 (audiences) and §7.6 (spend).

## Global Constraints

- Migration file `app/migrations/0026_ai_assist.sql` (Task 1); additions only; never edit migrations 0001–0025 (checksums).
- Nothing physically deleted: version tables immutable (trigger pattern of `source_versions` in `0004_notes.sql`), event tables append-only. `passages` rows are written once and never updated or deleted.
- Dates and times in UTC+8 (`todayUtc8`, `Asia/Kuala_Lumpur`).
- Limits (fixed in V1.0): question 1–500 characters; brief 1–2,000; report title 1–200; leave-out 0–1,000; draft and summary body up to 100,000; chosen sources/threads 1–10; summary input ≤ 120,000 characters; material budget ≤ 40 passages and ≤ 30,000 characters plus ≤ 20 record snapshots; ≤ 12 search terms; output tokens: answer 1,500, report 4,000, summary 2,000; default report period the last 14 days.
- Passage splitting: at blank lines; blocks > 1,500 characters split at sentence ends; blocks < 200 characters merge with the next; messages one passage unless > 1,500 characters.
- Every question, brief, title, leave-out text, draft edit and summary edit runs `findCredentials`; a finding refuses with exactly `Not posted: this looks like it contains <kinds>. Remove it and post again.` and stores nothing. The assembled AI input is checked too; a finding blocks the request with the kind named.
- Question, answer, draft, summary and leave-out text never written to `audit_events` or event rows (lengths and hashes allowed).
- Out-of-audience or not-visible content answers 404.
- Labels exactly: `AI answer — check the sources`; `AI draft — not approved`; `AI draft — not approved for sharing`; `Summary approved for sharing`; `Access review required`; `From a restricted source`; `Proposed — not authorised`; `This answer used information you can no longer read`; `This answer used information some people in this thread cannot read.`; `Nothing in this project matched your question`; `AI answer unavailable: <reason>`. AI outputs use the dashed outline class already used for AI proposals.
- Spend purposes `question_answer`, `report_draft`, `summary_draft`; every request charged to its requester's personal cap (`actorUserId` = requester); 3 attempts × 120 s; no retry of refusals, invalid credentials or exhausted allowance.
- No automatic runs in 4b; nothing in 4b calls `extraction.requestAutomatic`.
- No real organisation names or acronyms; test accounts only `*@example.org|com|net` or `*@kainow.test`.
- Tests: `KAINOW_TEST_DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/kainow_test`; DB tests with `--test-concurrency=1` (the `npm test` script); check no other session is running tests before a full suite.
- Never print or open `.env` files or API keys. Never use `git stash`.
- Commit after each task with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Uncited passages leaking on share:** the share check must use every passage *sent*, not only those cited — an uncited restricted passage can still shape the wording. Test: Task 6 `share is refused when an uncited sent passage is restricted`.
2. **A question with no searchable words** (only stop words, e.g. "apa yang ada?" or "what is it?"): must answer "Nothing in this project matched your question" with no AI call and no charge, not crash or send an empty input. Test: Task 3 `stop-word-only question yields no terms` and Task 5 `question with no terms makes no AI call`.
3. **Material hidden between asking and the job starting:** the dropped passage must not reach the AI and the answer must say so. Test: Task 4 `passage hidden after queueing is dropped at start`.
4. **Leave-out phrase written differently in the draft** (case, accents, a line break inside the phrase): still marked. Test: Task 9 `leave-out matching ignores case, accents and line breaks`.
5. **Project Deferred while a request waits:** ends `blocked` with no spend entry. Test: Task 4 `project deferred after queueing blocks without spend`.
