# Cross-project search — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One search over every project a person can currently read. It answers which project holds a half-remembered detail, and never shows anything the person could not already open.

**Architecture:**
- Migration `0019_search.sql` adds `pg_trgm` and one view, `search_documents`, with one `UNION ALL` branch per content kind and per source of earlier wording. Each branch has a trigram GIN index on exactly the expression it searches.
- A new `src/search/` module decides which projects the person can read, using `ProjectAccess` the same way as My Projects. It then runs one SQL statement over the view, which filters, removes duplicate items, cuts snippets, counts and limits.
- The web app gets a header search box, a `#/search` page, and item deep links into the Work and Notes tabs.

**Tech Stack:** TypeScript, NestJS, PostgreSQL 16 with `pg_trgm` (contrib, trusted), React + Vite, `node:test`. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-v1-search-design.md`

## Global Constraints

- Searchable kinds, closed list in this order: `project, person, note, ai_proposal, human_proposal, task, decision, question, risk`. Result order within a project: Project, People, Tasks, Decisions, Questions, Risks, Proposals (AI and human), Notes. Within a kind, newest first.
- Phrase: trim, NFC, split on whitespace, drop one-character words, keep at most 8 words. At least one word must have 3 or more characters. `q` is at most 200 characters. Escape `\`, `%` and `_`, then match `text ILIKE ALL(patterns)` with `%word%`.
- Exact copy:
  - `Type at least one word of 3 or more letters.`
  - `Search is limited to 200 characters.`
  - `Unknown kind: <value>.`
  - `Search took too long. Try more specific words.` (503)
  - `No matches in the projects you can see.`
  - `Searched N projects you can currently see` (`1 project` when N is 1)
  - `Search your projects` (header box label)
  - `Include archived projects`
  - `Only <project name>`
  - `Show all N in this project`
  - `Show more`
- Match notes, exact copy:
  - `Matched version <n> of <m>`
  - `Matched earlier wording`
  - `Matched wording before an amendment`
  - `Matched an answer`
  - `Matched the note's title` (title matches). This one is added by this plan; the spec gave the title row no note.
  - otherwise `null`
- Limits:
  - 10 results per project in the cross-project view;
  - 50 per page with `project`;
  - at most 30 projects;
  - snippet about 160 characters, with `…` where text was cut;
  - `statement_timeout` 5 seconds.
- Access is decided only by `ProjectAccess`: `visibleProjectIds`, then `load()`; a project is kept if `roles.length > 0 || grantKinds.length > 0`. Archived projects are dropped unless `archived=1`. The view never decides access.
- An unreadable or malformed `project` filter gets the same answer as no matches (`projects: []`), never a 404.
- The search phrase is never written to `audit_events`, application logs or error bodies.
- Every row that comes from a note carries `source_id`. Rows whose note has `status = 'deleted'` are excluded through one predicate in the service (spec §5).
- Test accounts only: `*@example.org`, `*@kainow.test`. No organisation names.
- DB tests: one file at a time, `KAINOW_TEST_DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/kainow_test`.

**Deviation from the spec, decided here:** person rows in the view expose their membership's end date and a held/revoked filter. The service applies "Active or Scheduled today" with the app clock's `today`, not the database's `now()`, because tests and the app use the injected clock. The role and state shown for a person come from `ProjectContext.rows`, so they match the People tab exactly.

## Review Focus

1. **A search word containing `%`, `_` or `\`** (for example `50%` or `file_name`) must be taken literally, not as a wildcard (Task 2 unit test; Task 4 HTTP test).
2. **A person who holds two roles in one project, or appears in two projects,** gets one person result per project, listing both roles (Task 4).
3. **A note with many versions where only an old version matches** gets exactly one result. It opens `#/notes/:id/v/:n` and says `Matched version n of m`. If the current version also matches, the current one wins (Task 4).
4. **A phrase in Bahasa Melayu or with accented or mixed-case letters** such as `Mesyuarat PKX` matches case-insensitively with no stemming (Task 4).
5. **A grant holder whose grant lapses between two searches** drops out at once on the next search, with nothing cached (Task 4, through the fake clock).

### Task 1: Migration with the view and indexes

**Files:**

**Interfaces — produces:**
- `search_documents (project_id uuid, kind text, item_id uuid, source_id uuid NULL, run_id uuid NULL, version_no int NULL, version_count int NULL, is_current boolean, match_note text NULL, text text, ref_title text, status text NULL, at timestamptz, ends_on date NULL)`.
- Branches, each giving `text` as the exact indexed expression:

| kind | from | text | item_id | is_current / match_note | notes |
|---|---|---|---|---|---|
| `project` | `projects` | `name \|\| E'\n' \|\| purpose` | project id | true | `at` = `created_at`, `status` = project status |
| `person` | `memberships m JOIN users u` | `u.display_name` | `u.id` | true | only rows with `revoked_at IS NULL` and not held (`held_at IS NULL OR (restored_at IS NOT NULL AND restored_at >= held_at)`); `ends_on = m.expires_on`; `at = m.starts_on::timestamptz` |
| `note` | `sources` | `title` | source id | true, `Matched the note's title` | only `project_id IS NOT NULL`; `source_id` = id; `at` = `created_at` |
| `note` | `source_versions v JOIN sources s` | `v.text_content` | source id | `is_current` = highest `version_no` of the source; earlier → `Matched version <n> of <m>` (built in the service from `version_no`, `version_count`) | `ref_title` = `s.title`; `source_id` = `s.id` |
| `ai_proposal` | `extraction_items x` (+ run, version, source) | `x.text \|\| E'\n' \|\| x.quote` | item id | current when the item has no edits; else earlier, `Matched earlier wording` | only `x.review_status <> 'approved'`; `run_id`, `source_id` set |
| `ai_proposal` | `extraction_item_edits e JOIN extraction_items x` | `e.text` | `x.id` | current = newest edit (`edited_at DESC, id DESC`); others earlier | same filters |
| `human_proposal` | `human_proposals` | `text` | id | true | `review_status <> 'approved'` |
| `task` | `tasks` | `title` | id | true | `at = authorised_at` |
| `task` | `task_events e JOIN tasks t` | `e.detail->'title'->>'from'` | `t.id` | false, `Matched wording before an amendment` | `e.kind = 'amended' AND e.detail ? 'title'` |
| `decision` | `decisions` | `statement \|\| E'\n' \|\| coalesce(rationale, '')` | id | true | `status` |
| `question` | `questions` | `text` | id | true | |
| `question` | `question_answers a JOIN questions q` | `a.answer` | `q.id` | true, `Matched an answer` | `ref_title` = `q.text` |
| `risk` | `risks` | `description \|\| E'\n' \|\| coalesce(mitigation, '')` | id | true | |

- `ref_title` is the item's display title: project name, person name, note title, the proposal wording in force (the newest edit's text, else `x.text`), the current task title, the statement, the question text, the description.
- Indexes: `CREATE INDEX … USING gin ((<expression>) gin_trgm_ops)` on each base table, with the same `WHERE` as the branch where the branch filters (for example `task_events … WHERE kind = 'amended'`). Name them `search_<table>_trgm`.

### Task 4: Search service and API

**Files:**

- Modify: `app/src/app.module.ts` (import `SearchModule` after `ChangesModule`)

**Interfaces:**
- Consumes: `ProjectAccess` (exported by `ProjectsModule`), `loadArchiveState` (Task 3), `parsePhrase` / `parseKinds` / `parseOffset` / `hrefFor` / `KIND_ORDER` (Task 2), the view (Task 1), `membershipState` and `ROLE_LABEL`.
- Produces:
  - `GET /search` with `@AnySignedInUser()`.
  - `SearchService.search(user: AuthUser, query: Record<string, unknown>): Promise<SearchResponse>`.
  - `SearchService.timeoutMs = 5000`, a public field that tests may lower.
  - `export interface SearchResult { kind: SearchKind; id: string; title: string; snippet: string | null; matchNote: string | null; status: string | null; href: string }`
  - `export interface SearchProject { id: string; name: string; status: ProjectStatus; archived: boolean; myAccess: { roles: ProjectRole[]; grant: GrantKind | null }; total: number; results: SearchResult[] }`
  - `export interface SearchResponse { searched: number; projects: SearchProject[] }`

**How the service works:**
1. Parse the phrase and parameters.
2. Find the readable projects: `visibleProjectIds`, then `load()` and keep projects with `roles` or `grantKinds`, then `loadArchiveState` and drop archived ones unless `archived === '1'`. `searched` is the count of what remains.
3. If `project` is given and is not in that set, return `{ searched, projects: [] }`.
4. Open a client, run `BEGIN READ ONLY` and `SET LOCAL statement_timeout = <timeoutMs>`, and run one statement:
   - **`hits`:** rows of `search_documents` where
     - `project_id = ANY($ids)`;
     - `kind = ANY($kinds)`;
     - `text ILIKE ALL($patterns)`;
     - `(source_id IS NULL OR EXISTS (SELECT 1 FROM sources s WHERE s.id = source_id AND s.status <> 'deleted'))`, the one note predicate (comment it as the place O09 and sub-project 5 extend);
     - `(kind <> 'person' OR ends_on IS NULL OR ends_on >= $today::date)`.
   - **`best`:** `DISTINCT ON (project_id, kind, item_id)`, ordered by `is_current DESC, version_no DESC NULLS LAST, at DESC`.
   - **`ranked`:** `row_number()` per project in the order kind-rank (a `CASE` from `KIND_ORDER`) then `at DESC, item_id`, plus `count(*) OVER (PARTITION BY project_id)`.
   - **Selection:** rows with `rn <= 10`, or `rn > offset AND rn <= offset + 50` when `project` is given.
   - **Snippet in SQL:**
     ```
     p := strpos(lower(text), lower(first word))
     start := greatest(p - 60, 1)
     snippet := (CASE WHEN start > 1 THEN '…' ELSE '' END)
                || substr(text, start, 160)
                || (CASE WHEN start + 160 <= length(text) THEN '…' ELSE '' END)
     ```
     Collapse runs of whitespace to one space.
5. Commit, then build the response:
   - Projects in `lower(name), id` order; at most 30.
   - Person results: `title` = the name. `snippet` = the person's roles in that project from `ctx.rows` where `membershipState` is `active` or `scheduled`, as `ROLE_LABEL`s joined by `, `, then ` · Active` or ` · Scheduled`.
   - `matchNote` for earlier note versions = `Matched version <n> of <m>`.
   - `href` via `hrefFor`.
6. Errors: PostgreSQL `57014` (query cancelled) becomes `ServiceUnavailableException('Search took too long. Try more specific words.')`. Any other error is rethrown without the phrase in its message.
